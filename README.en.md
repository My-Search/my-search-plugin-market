# My Search · Plugin Market

> [中文](./README.md) | **English**

This repository is the **plugin market** for the "My Search" desktop app: it hosts both
the official plugin packages and the market index.

## Architecture: a two-layer index

There are two index files at the repository root, with distinct roles:

| File | Written by | Contents | Read by |
| --- | --- | --- | --- |
| `index.json` | **maintained by hand** | Source list: official plugin paths + third-party repos | our build tool |
| `index.dist.json` | **generated by the tool** | Full index: versions, sha256, download URLs… | **the client** |
| `index.error.json` | generated by the tool | Excluded items and why | developers, for self-checking |

The client reads:

```
https://raw.githubusercontent.com/My-Search/my-search-plugin-market/main/index.dist.json
```

### `index.json` format

```jsonc
{
  "official-repo": [
    // Official plugins: packages are archived by version in this repository
    "official-plugins/com.mysearch.pi-agent"
  ],
  "three-parties": [
    // Third-party plugins: user/repo, one plugin per repository
    "zhuangjie/github-file-upload"
  ]
}
```

**Adding a plugin**: after review, add one line here. The developer can then publish
releases without us touching this file again.
**Repository 404**: the build tool automatically removes dead repositories from
`three-parties`.

> Want to publish your own plugin? See the
> [Plugin Development & Publishing Guide](./docs/plugin-market-publish.en.md).

## Where packages live

### Official plugins: archived by version (repository files)

```
official-plugins/
  com.mysearch.pi-agent/
    2.5.2/com.mysearch.pi-agent.mspp
    2.6.0/com.mysearch.pi-agent.mspp    ← add a version directory for a new release
```

The build lists every version directory and **picks the highest version**. No Release is
needed for official plugins.

### Third-party plugins: your own repository + a Release

One plugin per repository. The spec is in the
[Plugin Development & Publishing Guide](./docs/plugin-market-publish.en.md)
([中文](./docs/plugin-market-publish.md)):

- **tag = plugin id** (e.g. `com.yourname.my-plugin`), stable and never changing
- **asset name = `<plugin-id>.mspp`**
- the `id` inside the package's `plugin.json` must match the tag (checked at build time)

## How the index updates

[`.github/workflows/build-index.yml`](./.github/workflows/build-index.yml) rebuilds
**hourly**:

1. read `index.json`
2. resolve each entry (list version directories for official plugins / download the
   Release package for third-party ones)
3. compute sha256, validate the manifest inside the package, pick the highest version
4. generate `index.dist.json` and `index.error.json` and **commit them back to the repo**
5. the client picks up the new index on its next read

The whole process only needs this repository's own `GITHUB_TOKEN` and **depends on no
extra secret** — because the index is a repository file, not a Release asset.

## Build errors

Items that don't meet the spec never enter `index.dist.json`; the reason is written to
[`index.error.json`](./index.error.json) for developers to check themselves. Common causes:

- the repository does not exist (404 — it is also removed from `index.json` automatically)
- the tag is not in "plugin id" form
- the `id` inside the package does not match the tag
- the manifest inside the package fails validation, or the version does not match the
  directory name

## Client-side download URL constraints

Every `downloadUrl` in the index is validated by the client and must satisfy:

- https
- host is `github.com` (Release assets) or `raw.githubusercontent.com` (official plugin
  directories)
- the path is either a Release asset path or
  `.../official-plugins/<id>/<version>/<id>.mspp`
- no userinfo, and the port is absent or 443
- downloads do not follow redirects automatically (each hop is validated, to prevent SSRF)
